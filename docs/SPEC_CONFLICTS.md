# Project Setu: Specification and Implementation Conflicts

This document records architectural, behavioral, and parametric differences between Project Setu Comprehensive Technical Report v3 (September 2026), the repository documentation, and the active codebase. Every item concludes with an explicit status label.

| Topic | Report v3 Specification | Current Codebase | README Documentation | Impact Analysis | Human Decision Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Packet Timestamp** | Unix epoch timestamp (4 bytes) required for rescue timeline reconstruction. | `shared/include/setu/packet.hpp` includes 4-byte `ts` field at byte offsets 18 to 21. | Corrected to match code and report. | High value for time synchronization and latency tracking. 25-byte frame capacity fully utilized. | **CONFIRMED**: Retain 4-byte unix timestamp in the 25-byte wire frame. |
| **Altitude Telemetry** | Lists 3D positioning with vertical elevation. Hardware matrix contains no barometer (ESP32-S3, SX1262, INMP441, MPU-6050, NEO-6M, ERM, LEDs, button, 1000 mAh LiPo). | Altitude is derived from NEO-6M GNSS NMEA sentences when available. Not encoded in the 25-byte packet. | Omitted from wire protocol table. | Rescuers see 2D coordinates in packet. Vertical altitude is local GNSS telemetry. | **CONFIRMED**: Altitude is GNSS derived. Stays out of the 25-byte wire frame for Phase 1. Displayed as local wristband telemetry in Setu Twin. |
| **BLE Short-Hop Tier** | Lists BLE short-hop mesh tier between adjacent wristbands to conserve sub-GHz airtime. | Not implemented in C++ core, firmware tasks, or simulation world. | Not documented in system architecture. | LoRa handles all hops directly. BLE tier deferred. | **CONFIRMED**: BLE stays off for Phase 1. |
| **RF Frequency Band** | Cites sub-GHz operations with regional regulatory tuning. | Hardcoded to 868 MHz with reference loss 31.2 dB at 1 meter. | References 868 MHz European and Asian ISM band. | India operates at 865 to 867 MHz under GSR 564(E). EU uses 868 MHz. US uses 915 MHz. | **UNVERIFIED**: Band presets (IN865, EU868, US915) marked unverified until project owner confirms target deployment. |
| **Duty-Cycle Override** | Requires regulatory compliance while preserving emergency signaling. | `priority_ignores_duty` configurable per scenario via `priority_bypass_duty`. | Stated 1 percent duty cycle without highlighting emergency priority bypass. | Priority SOS can bypass hourly 36-second budget if enabled. Relays enforce compliance. | **CONFIRMED**: Duty-cycle bypass is an explicit scenario option. Disaster-exemption claims removed as unlicensed rules require verified regulatory filings. |
| **Validation Evidence** | Specifies validation framework and target tolerances. | Log-distance path loss, capture effect, and log-normal shadowing implemented from theoretical formulas. | Reconciled to theoretical model verification. | Theoretical model reproduces formulas but has not been calibrated against physical field measurements. | **CONFIRMED**: Every unmeasured parameter carries an assumed status label until bench measurements are completed. |
| **Battery Nominal Capacity** | Specifies 1000 mAh LiPo rechargeable wearable battery. | Baseline defaults to 300 mAh (labeled legacy). Non-baseline profiles (`idealized`, `field`) default to 1000 mAh. | Mentions wearable form factor without naming nominal mAh. | 1000 mAh provides realistic disaster operating lifetime. 300 mAh preserved for legacy baseline trace reproduction. | **CONFIRMED**: 1000 mAh in all non-baseline profiles. Baseline labeled legacy with 300 mAh. |
| **Button Timing Windows** | Short under 500 ms, double press gap under 600 ms, long hold 1500 ms or more, 500 to 1500 ms rejected. | `button.hpp` implements `short_max_ms = 500`, `double_gap_ms = 600`, `long_min_ms = 1500`. | Reconciled with code. | Code and Report v3 match. Rejection band prevents ambiguous presses during physical panic. | **CONFIRMED**: Code and Report v3 are authoritative ground truth. |
| **Button Hazard Mapping** | Short = General, Double = Medical, Long = Trapped. | `node.cpp` maps Short to General, Double to Medical, and Long to Trapped. | Reconciled with code. | Accurate hazard classification at the physical wristband. | **CONFIRMED**: Code and Report v3 are authoritative ground truth. |
| **Dead-Reckoning Algorithm** | Recommends inertial dead-reckoning integration. | Uses step-detection impulse cadence and random-walk drift ($0.8 \text{ m} \times \sqrt{\text{seconds}}$). | Summarizes dead-reckoning positional circles without naming step impulse method. | Step detection works well for walking survivors but cannot capture stationary trapped survivor arm movements. | **PENDING HUMAN DECISION**: Reconcile step detection with sensor fusion integration in Phase 2. |
