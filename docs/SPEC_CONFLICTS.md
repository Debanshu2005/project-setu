# Project Setu: Specification and Implementation Conflicts

This document records architectural, behavioral, and parametric differences between Project Setu Comprehensive Technical Report v3 (September 2026), the repository documentation, and the active codebase. Every item concludes with an explicit status label.

| Topic | Report v3 Specification | Current Codebase | README Documentation | Impact Analysis | Human Decision Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Packet Timestamp** | Unix epoch timestamp (4 bytes) required for rescue timeline reconstruction. | `shared/include/setu/packet.hpp` includes 4-byte `ts` field at byte offsets 18 to 21. | Previously omitted; corrected to match code and report. | High value for time synchronization and latency tracking. 25-byte frame capacity fully utilized. | **CONFIRMED**: Retain 4-byte unix timestamp in the 25-byte wire frame. |
| **Altitude Telemetry** | Lists 3D positioning with altitude for collapsed multistory structures. | Altitude exists in firmware adapter as local variable. Not encoded in 25-byte packet. | Omitted from wire protocol table. | Rescuers cannot distinguish between floors without vertical elevation. Adding altitude requires frame expansion or coordinate compression. | **PENDING HUMAN DECISION**: Keep 25-byte wire frame fixed unless explicit approval is granted to expand frame size or compress altitude. |
| **BLE Short-Hop Tier** | Lists BLE short-hop mesh tier between adjacent wristbands to conserve sub-GHz airtime. | Not implemented in C++ core, firmware tasks, or simulation world. | Not documented in system architecture. | Dense disaster zones might face elevated LoRa channel congestion without local BLE offloading. | **PENDING HUMAN DECISION**: Keep BLE short-hop tier deferred until project owner approves secondary link architecture. |
| **RF Frequency Band** | Cites sub-GHz operations with regional regulatory tuning. | Hardcoded to 868 MHz with reference loss 31.2 dB at 1 meter. | References 868 MHz European and Asian ISM band. | India license-free band operates at 865 to 867 MHz under GSR 564(E). EU uses 868 MHz. US uses 915 MHz. | **PENDING HUMAN DECISION**: Add scenario radio presets (IN865, EU868, US915, AS923) in Phase 2 without changing baseline behavior. |
| **Duty-Cycle Emergency Override** | Requires regulatory compliance while preserving life-safety signaling. | `priority_ignores_duty = true` in node logic. Originating SOS and ACKs bypass duty limits. Only relays obey 1 percent limit. | Stated 1 percent duty cycle without highlighting emergency priority bypass. | Originating wristbands will transmit even if the hourly 36-second budget is exceeded. Relays enforce compliance. | **PENDING HUMAN DECISION**: Confirm whether emergency priority override is defensible under target national radio authorities. |
| **Validation Evidence** | Specifies validation framework and target tolerances. | Log-distance path loss, capture effect, and log-normal shadowing implemented from theoretical formulas. | Previously claimed independent validation; corrected to theoretical model verification. | Theoretical model reproduces formulas but has not been calibrated against physical field measurements. | **CONFIRMED**: Every unmeasured parameter carries an assumed status label until bench measurements are completed. |
| **Battery Nominal Capacity** | Specifies 1000 mAh LiPo rechargeable wearable battery. | `ChannelParams` defaults to `battery_capacity_mah = 300.0`. | Mentions wearable form factor without naming nominal mAh. | 300 mAh capacity causes faster simulated depletion than real hardware. | **PENDING HUMAN DECISION**: Upgrade default capacity to 1000 mAh in field realism profile; preserve 300 mAh in baseline profile. |
| **Button Timing Windows** | Short under 500 ms, double press gap under 600 ms, long hold 1500 ms or more, 500 to 1500 ms rejected. | `button.hpp` implements `short_max_ms = 500`, `double_gap_ms = 600`, `long_min_ms = 1500`. | Stale README previously claimed 300 ms, 400 ms, and 1200 ms; now reconciled. | Code and Report v3 match. Rejection band prevents ambiguous presses during physical panic. | **CONFIRMED**: Code and Report v3 are authoritative ground truth. |
| **Button Hazard Mapping** | Short = General, Double = Medical, Long = Trapped. | `node.cpp` maps Short to General, Double to Medical, and Long to Trapped. | Stale README previously swapped Medical and Trapped; now reconciled. | Accurate hazard classification at the physical wristband. | **CONFIRMED**: Code and Report v3 are authoritative ground truth. |
| **Dead-Reckoning Algorithm** | Recommends inertial dead-reckoning integration. | Uses step-detection impulse cadence and random-walk drift ($0.8 \text{ m} \times \sqrt{\text{seconds}}$). | Summarizes dead-reckoning positional circles without naming step impulse method. | Step detection works well for walking survivors but cannot capture stationary trapped survivor arm movements. | **PENDING HUMAN DECISION**: Reconcile step detection with sensor fusion integration in Phase 2. |
